## Контекст проблеми

У [SC-10](gherkin_uc04.md) після розформування Squad його Mob залишаються у власності Player, без членства в загоні та без призначеного Task. За [ER-моделлю](../lab1/erd.mmd) один Task може бути призначений кільком Mob. Потрібно визначити, як сервіс знімає призначення Task і членство в загоні.

## Варіанти, що обдумувались

1. Знімати призначення Task і членство у Squad одним викликом для кожного Mob.
2. Спочатку знімати призначення Task, а потім окремим викликом знімати членство у Squad для кожного Mob.

## Обране рішення

Обрано другий варіант: для кожного Mob сервіс виконує `clearTaskAssignment(mobId)`, потім `clearSquadMembership(mobId)`

## Плюси та мінуси

1. Один виклик:
    - Плюс: сервіс виконує один виклик на Mob, що спрощує взаємодію з клієнтом і зменшує кількість звернень.
   - Мінус: порядок зняття двох зв’язків прихований усередині виклику, через що логіка розформування стає менш очевидною та складнішою для відстеження.

2. Два послідовні виклики:
   - Плюс: порядок є явним, і сервіс знімає призначення Task, поки Mob ще входить до Squad, що краще відповідає бізнес-логіці розформування.
   - Мінус: у разі збою між викликами потрібне спільне відкочування змін, що збільшує складність забезпечення атомарності операції.
